# NetBeans Event-Handler Guide: pasting the code with the Designer's built-in code handler

**Requirement covered:** every button click, slider change and card event in the game is wired with the
handler methods that the NetBeans Form Designer generates (double-click a component, or use the
**Events** tab). You do **not** write `addActionListener(...)` lines yourself.

Companion to `NETBEANS_GUIDE.md` (how to create the forms and name the components) and
`NETBEANS_DESIGN_SETTINGS_GUIDE.md` (every look/layout value, set in the Properties window).
Do those first. This guide covers what to do *after* the components exist and are styled.

**No design code in constructors:** fonts, colors, opaque, wrapping, alignment, borders, icons, sizes and
layout constraints are designer values, not code. The constructors you paste below therefore contain only
the `navigator` field and `initComponents();`.

The code in this guide is copied from the working project files, and was tested: 16 automated checks
confirm each handler runs exactly once per click. It was not tested inside NetBeans itself.

---------------------------------------------------------------------------------------------------
## 1. What the "built-in code handler" is

When you create an event in the designer, NetBeans does two things:

1. It writes an **empty method (a "stub")** in the editable part of your source file:

        private void playButtonActionPerformed(java.awt.event.ActionEvent evt) {
            // TODO add your handling code here:
        }

2. It writes the **registration** inside the grey, locked `initComponents()` block. This is the line
   that connects the button to your method. You never type or edit it.

Your only job is to **paste code between the braces of the stub**. That is why the code in this project is
organized as small handler methods: each one is exactly what you paste into a stub.

### The four rules
1. **Paste only inside the stub's braces.** Never touch the grey locked code.
2. **Never also keep an `addActionListener(...)` line** for the same component. The registration already
   exists in the locked block, so a second one makes every click run twice.
3. **If NetBeans names the stub differently** (for example `articleCardAremoveRequested`), keep NetBeans's
   name and paste only the body. The names in this guide are what NetBeans normally generates.
4. The handlers use the field `navigator`, so set up each class first (section 3).

---------------------------------------------------------------------------------------------------
## 2. How to create a handler (three ways, all give the same result)

**A. Double-click** the component in Design view. For a JButton this creates its `actionPerformed` handler
and jumps to the Source tab.

**B. Events tab** (needed for anything that is not the default event):
1. Click the component in Design view (or in the **Navigator** window, bottom left).
2. In the **Properties** window, click the **Events** button (the lightning-bolt icon at the top).
3. Find the event row (e.g. `actionPerformed`, or `stateChanged` under **change**).
4. Click the `...` button at the right of that row, or its dropdown, and choose **Add**.
   NetBeans creates the stub and jumps to the Source tab.

**C. Right-click** the component -> **Events** -> the group (e.g. Action) -> the event.

After NetBeans jumps to the Source tab, the cursor is inside the new stub. Select the line
`// TODO add your handling code here:` and replace it with the code from this guide.

To reuse an existing handler for another component, open the event's dropdown in the Events tab and pick
the existing handler name instead of creating a new one.

## 4. The handlers: component by component

### 4.1 CollapsibleCard (inside the card form)

The card handles its own two buttons, then tells the screen through a *card event*.

**`toggleButton` -> actionPerformed**  
Double-click the button.

```java
private void toggleButtonActionPerformed(java.awt.event.ActionEvent evt) {
    setExpanded(!expanded);
    fireToggled();
}
```

**`removeButton` -> actionPerformed**  
Double-click the button.

```java
private void removeButtonActionPerformed(java.awt.event.ActionEvent evt) {
    fireRemoveRequested();
}
```

Also paste these supporting methods anywhere in the class (they are normal code, not handlers). They are what makes the **card** events show up in the Events tab of every card on a form:

```java
/** Registers a listener. Having this pair of methods is what makes "card" events appear in the designer. */
public void addCardListener(CardListener listener) {
    listenerList.add(CardListener.class, listener);
}

public void removeCardListener(CardListener listener) {
    listenerList.remove(CardListener.class, listener);
}

private void fireToggled() {
    CardEvent evt = new CardEvent(this, expanded);
    for (CardListener l : getListeners(CardListener.class)) {
        l.toggled(evt);
    }
}

private void fireRemoveRequested() {
    CardEvent evt = new CardEvent(this, expanded);
    for (CardListener l : getListeners(CardListener.class)) {
        l.removeRequested(evt);
    }
}
```

`CardEvent.java` and `CardListener.java` are plain classes (not forms). Add them to the package as they are in the project, then **Clean and Build** before using the card on `GameplayPanel`.

## 5. Checking your work

Run the game and press each control once.

| You do this | Expected |
|---|---|
| Play (menu) | tutorial appears, one click sound |
| Settings -> move the slider | label shows the new volume, a short preview sound plays when you let go |
| Start Game | first level, main news enlarged, countdown running |
| Enlarge / Minimize on any card | that card opens/closes **once** (not open-then-closed) |
| REMOVE ARTICLE A/B | one confirmation dialog, then the result |
| Next Level | next level begins |
| Main Menu (in game) | back to the menu, game music stops |

### Common problems
| Symptom | Cause | Fix |
|---|---|---|
| A click seems to do nothing, or a card opens and immediately closes | the same component is wired **twice** (stub + leftover `addActionListener`, or two stubs on one event) | delete the extra one; keep only the generated one |
| `cannot find symbol: navigator` | the field and `this.navigator = navigator;` were not added | section 3 |
| `cannot find symbol: playButtonActionPerformed` after deleting a stub | the locked registration still points to it | in the Events tab, clear that event, or recreate the stub |
| Stub has a different name | NetBeans naming | keep NetBeans's name, paste only the body |
| No **card** group in the Events tab | the card is not compiled as a bean yet | Clean and Build, reopen the form |
| A sound plays once when the Settings screen is built | your NetBeans registers the slider handler before applying the `value` property | harmless (same volume); ignore it |
| Red underline on `Font`, `Color`, `JViewport`, `BufferedImage`... | a pasted method needs an `import` the new file does not have yet | click the red lightbulb and choose the import, or press **Alt+Shift+I** (Fix Imports) |
| Handler seems to be missing from the file | you edited inside the locked grey block | undo, and paste only inside the stub braces |

## 7. Other places NetBeans lets you put code (for reference)

- **Properties -> Code tab** of a component (also right-click -> **Customize Code**): *Pre-Creation*, *Custom
  Creation*, *Post-Creation* and *Post-Init* code. NetBeans copies this text into the locked
  `initComponents()`. This project uses *Post-Init Code* for the sprite skins of the progress bars, the
  dialogue-box border and the card's scroll pane; see `NETBEANS_DESIGN_SETTINGS_GUIDE.md`.
- **Custom constructor code**: anything after the `initComponents();` call, as in this project.
